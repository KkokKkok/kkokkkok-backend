# 마이 페이지

`GET /api/profile`, `X-Installation-Id: <UUID>` 필수. 파일럿 모드는 Bearer 인증 기기 식별자로 대체한다.

```json
{
  "dataScope": "installation",
  "displayName": "테스터",
  "photoChecks": 2,
  "protectionEdits": 1,
  "cumulativeChecks": 0,
  "sensitivePlaces": [{"name":"집", "category":"home"}],
  "storagePolicy": {"autoDeleteOriginals":false,"retention":"until_user_deletes"}
}
```

사진 검사는 원본 사진의 완료된 검사 작업 수(다량 검사 각 항목 포함, 편집 후 재검사 제외), 보호 편집은 원본 사진의 완료된 편집 작업 수, 누적 분석은 해당 기기에 등록된 장소의 실행 기록 수이다. 검사 결과의 위험도나 AI 품질을 나타내는 통계가 아니며 개발용 모의 실행 기록도 작업 수에 포함한다. 파일럿 모드에서는 해당 기기 소유 사진만 집계한다. 로컬 단독 개발 모드에서는 사진은 기존 공용 저장소 범위, 장소와 누적 분석은 요청 기기 범위다.

원본과 편집 이미지는 직접 삭제하기 전까지 보관한다. 자동 삭제는 꺼져 있고 기간 변경 API는 제공하지 않는다. 로그인 계정 정보가 없어 이름은 테스터다. 사진이나 GPS 좌표는 응답하지 않는다. 기록이 없으면 0과 빈 목록을 반환한다. 인증 오류는 기존 공통 오류 형식을 따른다.

## 전체 데이터 삭제

`DELETE /api/profile/data`, 동일 인증/기기 헤더, 성공 시 `204 No Content`.
원본·편집 사진, 단독/다량 검사와 편집/재검사 기록, 등록 민감 장소·사진 연결 및 누적 분석 결과를 삭제한다. Node의 원본·분석본·미리보기와 검사 결과도 삭제한다. 파일럿 등록/초대 토큰은 유지하므로 다시 자료를 추가할 수 있다. 휴대폰 갤러리에 내보낸 파일과 사용자가 별도로 만든 백업은 삭제 대상이 아니다.

파일럿에서는 인증 기기 소유 자료만 삭제한다. **로컬 공용 개발 모드는 사진·검사·편집이 모두 공용이므로 공용 사진과 기록 전체**, 장소/누적 결과는 요청 기기의 자료를 삭제한다. 파일럿 다중 사용자 운영에서는 반드시 인증을 켠다.

분석/편집 또는 다른 요청 진행 중에는 `409 DATA_IN_USE` / `DATA_BUSY`로 대기 후 재시도한다. 분석 서버 불통이나 파일 삭제 실패는 5xx이며 완료가 아니다. 외부 파일 삭제가 일부 진행될 수 있으며 DB 메타데이터를 남겨 같은 DELETE 재시도로 정리한다(중간 상태에서 기존 기록 재열기는 실패할 수 있다). 없는 Node 검사/로컬 파일은 삭제된 것으로 처리한다. 모든 외부 자료를 정리한 후 DB 메타데이터를 짧은 트랜잭션으로 삭제한다.

현재 요청 간 동시 삭제 보호는 단일 Spring 인스턴스 기준이다. 여러 인스턴스로 확장할 때는 공유 삭제 잠금/작업 큐가 필요하다. S3 사용 시 이전 버전과 삭제 마커까지 정리하며 ListBucketVersions/DeleteObjectVersion 권한이 필요하다. 이 권한 설정은 준비만 했고 실제 AWS 검증/배포는 수행하지 않았다. 별도 운영 백업은 이 API에서 관리하지 않는다.
